# VCare v0.1 Prototype Implementation Plan

Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working prototype where clinic staff run one live queue per doctor session (online, phone and walk-in patients), patients follow their estimated turn from a link, and simulated leave-now alerts fire based on travel time.

**Architecture:** Pure TypeScript modules in `src/domain` hold the queue rules, estimates and alert planning with no I/O, so they are unit tested with fixed clocks. `src/server` wraps them in Postgres transactions (session row lock), an append-only event log, a notification outbox and `NOTIFY` for live updates. Next.js route handlers and pages stay thin. A separate worker process runs the alert sweep and delivers the outbox.

**Tech Stack:** Node 20+ (local is 23.7), npm, Next.js App Router (latest from create-next-app), React, Tailwind, TypeScript strict, PostgreSQL 17 in Docker, Drizzle ORM + drizzle-kit, node-postgres (`pg`), zod 4, Vitest, tsx.

**Spec:** `docs/spec.md`

## Global Constraints

- Defaults (put in `DEFAULTS`, Task 1): grace 10 min, alert buffer 10 min, slot 15 min, default consult 8 min, travel options 10/20/30/45/60, delay alert threshold 20 min, max 2 delay alerts, duration samples: last 50 within 30 days, at least 5, each clamped to 1-60 min.
- All timestamps are `timestamptz`. Clinic timezone defaults to `Asia/Kolkata`. Every time shown to a person goes through `formatClinicTime` (Task 4) in the clinic's timezone. Tests must pass with the process in UTC (`TZ=UTC`).
- Domain functions take `now: Date` as an argument. Nothing in `src/domain` reads the clock, the network or the database.
- Every queue change goes through `applyAction` (Task 7) or the public booking functions (Task 8), which lock the session row, write a `queue_events` row and publish a change.
- Patient data is limited to name, phone (optional for walk-ins), booking, queue state and travel minutes. No clinical fields.
- Patient-facing responses never contain another patient's name or phone.
- Notifications are simulated in v0.1. No messaging provider SDKs.
- Error responses are `{ "error": { "code": QueueErrorCode, "message": string } }`.
- Commits: one logical change each, short lowercase messages, no trailers. Never commit `.env`.
- No code comments, commit messages or copy mention AI tools.

## Review Focus

1. Two receptionists (or one double tap) press Next at the same moment: exactly one patient advances, the other request gets 409 and the page refreshes. Test: Task 7, "concurrent NEXT".
2. Phone numbers typed in any common Indian format, and walk-ins with no phone: formats normalize to `+91XXXXXXXXXX`, junk gets a 400 with a readable message, no phone means no notifications and no crash. Tests: Task 4 (normalize), Task 7 (walk-in with and without phone).
3. Server in UTC while the clinic is in IST: a 10:00 schedule creates a session starting at 04:30Z, and displayed times are clinic times. Tests: Task 6 (materialize), Task 4 (`formatClinicTime`, `clinicDateString`).
4. Booking requests for a time that is not a free slot (10:07, at session end, already taken, in the past, two people racing for one slot): rejected, never double booked. Tests: Task 8.
5. A guessed patient token, or staff of one clinic using another clinic's session id: 404 with no data. Tests: Task 8 (board, token), Task 12 (routes).

- Consumes: `QueueEntryView`, `EntryStatus` (Task 1)

```ts
export function orderKey(e: QueueEntryView, graceMinutes: number): Date;
export function compareEntries(a: QueueEntryView, b: QueueEntryView, graceMinutes: number): number;
export function callableQueue(entries: QueueEntryView[], graceMinutes: number): QueueEntryView[];
export function hasLostSlot(e: QueueEntryView, now: Date, graceMinutes: number): boolean;
export function projectedLine(entries: QueueEntryView[], now: Date, graceMinutes: number): QueueEntryView[];
export function planNext(entries: QueueEntryView[], graceMinutes: number):
  { completeId: string | null; startId: string | null; passedIds: string[] };
```

Rules (from the spec):
- `orderKey`: walk-in (`scheduledAt === null`) uses `checkedInAt`. Appointment uses `checkedInAt` only when `checkedInAt` and `passedAt` are set and `checkedInAt > passedAt + grace`; otherwise `scheduledAt`.
- `compareEntries`: prioritized (`priorityAt` set) first, by `priorityAt`; then `orderKey`; then `ticketNo`.
- `callableQueue`: `CHECKED_IN` only, sorted.
- `hasLostSlot`: `BOOKED` and `passedAt` set and `now >= passedAt + grace`.
- `projectedLine`: `CHECKED_IN` plus `BOOKED` entries without a lost slot, sorted.
- `planNext`: `completeId` = the `IN_CONSULTATION` entry; `startId` = first of `callableQueue`; `passedIds` = `BOOKED` entries with `passedAt === null` whose `orderKey` is earlier than the started entry's, unless the started entry is prioritized (then none).

### Task 3: Duration stats and ETA projection

**Files:**
- Create: `src/domain/estimate/durations.ts`, `src/domain/estimate/eta.ts`
- Test: `tests/domain/durations.test.ts`, `tests/domain/eta.test.ts`

**Interfaces:**
- Consumes: `projectedLine` (Task 2), `DurationStats`, `Eta`, `SessionTiming`, `DEFAULTS` (Task 1)
- Produces:

```ts
export function durationStats(samplesMinutes: number[], defaultMinutes: number): DurationStats;
export function projectEtas(input: {
  entries: QueueEntryView[]; session: SessionTiming; stats: DurationStats; now: Date; graceMinutes: number;
}): Eta[];
```

`durationStats`: clamp each sample to [1, 60]; fewer than 5 samples gives `{ median: default, p25: default * 0.75, samples: n }`; otherwise linear-interpolated percentiles (position `p * (n - 1)` on the sorted array).

`projectEtas` algorithm:

```
if session.closedAt: return []
base = now
if !doctorArrivedAt: base = max(now, expectedStartAt ?? startsAt)
if pausedUntil > now: base = max(base, pausedUntil)
cur = entry with status IN_CONSULTATION
elapsed = cur ? minutes(now - cur.startedAt) : 0
tExp   = base + (cur ? max(median - elapsed, 1) : 0)
tEarly = base + (cur ? max(p25 - elapsed, 0) : 0)
for (i, e) of projectedLine(entries, now, grace):
  floor = e.status == BOOKED ? e.scheduledAt : -inf
  exp = max(tExp, floor); early = max(tEarly, floor)
  emit { entryId: e.id, position: i + 1, expectedAt: exp, earlyAt: early }
  tExp = exp + median
  if e.status != BOOKED: tEarly = early + p25      // early estimate skips absent bookings ahead
```

Message copy:

Action schema (zod 4; `name` = `z.string().trim().min(1).max(80)`, `iso` = `z.iso.datetime({ offset: true })`):

| type | fields | effect |
| --- | --- | --- |
| `NEXT` | `expectedCurrentId: z.uuid().nullable()` | `CONFLICT` if the current consult id differs. Apply `planNext`: complete current (`completed_at`), start next (`started_at`), set `passed_at = now` on `passedIds`, `doctor_arrived_at` if null, clear break. `EMPTY_QUEUE` only when there is nothing to complete and nobody to start |
| `COMPLETE_CURRENT` | `expectedCurrentId: z.uuid()` | complete current; `CONFLICT` if it differs |
| `CHECK_IN` | `entryId` | `BOOKED -> CHECKED_IN`, `checked_in_at = now` |
| `RECHECK_IN` | `entryId` | `NO_SHOW -> CHECKED_IN`, `checked_in_at = now` |
| `MARK_NO_SHOW` | `entryId` | `-> NO_SHOW`, `passed_at = coalesce(passed_at, now)` |
| `CANCEL` | `entryId`, `reason?` (max 200) | `-> CANCELLED` |
| `PRIORITIZE` | `entryId`, `reason` (3-200 chars) | entry must be `CHECKED_IN`; sets `priority_at`, `priority_reason` |
| `ADD_WALK_IN` | `name`, `phone?` | `insertEntry` channel `WALK_IN` |
| `ADD_PHONE_BOOKING` | `name`, `phone`, `scheduledAt: iso` | `insertEntry` channel `PHONE` |
| `DOCTOR_LATE` | `expectedStartAt: iso` | must be after now and doctor not arrived |
| `DOCTOR_ARRIVED` | none | `doctor_arrived_at = coalesce(.., now)` |
| `START_BREAK` | `until: iso`, `reason?` | until within (now, now + 4 h]; completes current; sets `paused_until`, `pause_reason` |
| `END_BREAK` | none | clears break |
| `SET_NOTE` | `note: string (max 200) \| null` | sets `public_note` |
| `CLOSE_SESSION` | none | completes current, cancels `BOOKED`/`CHECKED_IN` with reason `session closed`, sets `closed_at` |

`NEXT`, `COMPLETE_CURRENT`, `CHECK_IN`, `RECHECK_IN`, `ADD_WALK_IN`, `DOCTOR_ARRIVED`, `START_BREAK` and `END_BREAK` require `session.date === clinicDateString(now, timezone)`, else `VALIDATION` "Only today's session can be run". Every action runs in one transaction: `lockSession`, validate with `assertTransition`, write, `recordEvent` (type = action type, actor staff id), `publishSessionChanged`.   lostSlots: number; etaMaeMinutes: number | null }

Seed: clinic "Demo Clinic", slug `demo`, timezone `Asia/Kolkata`; Dr. Meera Nair (General Physician, Mon-Sat 10:00-13:00 and 17:00-20:00) and Dr. Arjun Rao (Paediatrics, Mon-Sat 10:00-13:00); staff `reception@demo.test` (RECEPTIONIST) and `meera@demo.test` (DOCTOR) with password `SEED_STAFF_PASSWORD` (exit with a message if unset). Simulator: session 10:00-13:00, 15-min slots, booked patients on every second slot from 10:00, minute steps until everyone is seen. Defaults: seed 1, 6 walk-ins/hour, 8 bookings, doctor on time, median 8, grace 10, buffer 10. Separate seeded generators (mulberry32) for walk-in arrivals, consultation lengths (lognormal, sigma 0.4 around the median, clamped 2-40, fixed per patient) and travel (from the options, actual travel = chosen + uniform -3..+5 min), so both worlds see the same patients. Both worlds use `planNext` when the doctor is present and the current consult has run its length. In the **alerts** world booked patients leave when `planAlerts` first returns LEAVE_NOW for them. In **baseline** they arrive 5 minutes before their slot. Wait = start - arrival. `etaMaeMinutes` = mean |expected at alert time - actual start| (alerts world only). A lost slot = checked in after `passedAt + grace`. When late, the doctor arrives `doctorLateMinutes` after 10:00; if `lateAnnounced`, `expectedStartAt` is set at 09:30.
